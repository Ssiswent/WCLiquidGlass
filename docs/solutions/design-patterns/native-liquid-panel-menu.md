# 原生 Liquid Glass 液态面板菜单

## 目标

WCLiquidGlass 的液态面板菜单使用 UIKit 原生 `UIToolbar` 与
`UIBarButtonItem(menu:)` 作为悬浮入口和菜单锚点。插件只负责把这个系统按钮放到
微信页面上、同步菜单内容和处理位置生命周期；菜单展开、收起、玻璃形变与按钮按压
动画全部交给 UIKit。

这条路径与设置页测试 App 中验证过的独立 Toolbar 实现保持一致，避免普通
`UIButton` 的交互式 Glass 背景与菜单转场叠加造成掉帧。液态面板不依赖 WCGlass
才能工作；如果 WCGlass 同时存在，兼容层只在检测到对应运行时对象并满足页面状态时
接管既有兼容修复。

## 用户可见行为

### 菜单样式

在设置页的菜单样式中选择：

- **环形菜单**：使用插件自己的非抢焦点覆盖窗口，支持拖动后沿边缘展开动作。
- **液态面板**：使用系统 Toolbar 按钮和系统 `UIMenu`，菜单从悬浮按钮位置展开。

液态面板的菜单尺寸使用系统菜单样式选项（Small、Medium、Large 或自动），不在
插件内复制菜单容器。菜单顶部不增加额外的插件标题。

### 悬浮按钮

两种菜单样式都支持拖动按钮。松手后按钮吸附到距离最近的屏幕边缘，并保存：

- 左侧或右侧锚点；
- 可见区域内的垂直位置比例。

位置写入插件偏好设置，微信退出后再次启动仍从上次位置创建，不回退到右下角默认
位置。首次创建时才使用默认锚点和垂直位置。

按钮停止操作 0.5 秒后进入半隐藏状态，只保留靠近屏幕边缘的可命中部分；隐藏不会
改变已保存位置。点击露出部分时，系统菜单仍以当前按钮位置作为 source view，不把
按钮瞬移到右下角。

### 隐藏按钮轨迹

设置页不暴露内部策略名，提供两种用户可理解的选择：

1. **隐藏位置直接打开菜单**：保持按钮的隐藏锚点，点击露出部分直接从当前位置打开
   系统菜单。
2. **点击时先自动归位**：先使用系统按钮的恢复/弹簧轨迹回到完整可见位置，再让
   `UIBarButtonItem` 打开菜单。

两种轨迹都取消旧的隐藏、吸附或恢复事务后再响应新的触摸，避免拖动、自动隐藏和
菜单打开同时修改同一几何状态。菜单关闭后重新启动 0.5 秒空闲计时。

## 菜单内容同步

菜单内容不在 Toolbar 初始化时永久固定。每次准备打开菜单前，插件按以下顺序同步：

1. 读取当前可见控制器、导航栈和真实 TabController。
2. 根据当前页面过滤聊天工具、主页 Tab 和设置入口等动作。
3. 读取“按钮与动作”中的持久化顺序；不可用动作暂时隐藏，不从配置中删除。
4. 为每个动作解析微信当前主题素材，缺失时使用插件的系统图标回退。
5. 只有动作标识、顺序或图标发生变化时才重建 `UIMenu`，避免在展开期间重复刷新
   菜单树。

动作执行仍调用微信已有的控制器或工具栏入口。找不到安全的原生目标时，插件只给出
中文提示，不强行调用未知私有接口。

## 实现边界

- `UIToolbar` 和 `UIBarButtonItem(menu:)` 是菜单动画的唯一来源；插件只对同一个
  Toolbar frame 做恢复、拖动吸边和半隐藏平移动画，不复制按钮或菜单视图。
- Toolbar 与外层菜单窗口都不裁剪超出 bounds 的内容，以便系统菜单从 source view
  连续形变到完整菜单。
- 悬浮按钮拖动只在按钮自身的命中路径处理；页面其它区域继续透传给微信。
- iOS/微信系统首次建立 Liquid Glass 渲染资源时，系统可能出现低概率首帧闪层；
  这属于 UIKit/Render Server 的冷启动预热边界，不由插件业务线程重绘触发。

## 验证清单

- 冷启动后分别点击导航栏按钮和液态面板按钮，比较系统菜单形变。
- 在左、右两侧拖动按钮，关闭并重新启动微信，确认左右锚点和垂直位置保持。
- 等待半隐藏后点击露出部分，确认菜单从隐藏位置打开；再测试“点击时先自动归位”，
  并确认关闭菜单后 0.5 秒进入半隐藏。
- 在菜单展开、收起、自动隐藏和拖动之间快速交错操作，确认没有瞬移、重复菜单或
  按钮失去命中。
- 切换微信 Tab、进入聊天和返回设置页，确认菜单项目与当前页面同步。
